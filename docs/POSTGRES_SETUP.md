# PostgreSQL setup and migrations

Requires PostgreSQL 14+ with the `pgvector` extension and a role allowed to run `CREATE EXTENSION`.

```bash
docker compose -f infrastructure/docker-compose.yml up -d          # postgres (pgvector image) + redis
cd services/api && pip install -r requirements.txt
export DATABASE_URL=postgresql+psycopg://astera:astera@localhost:5432/astera
alembic upgrade head                                               # creates the vector extension, then all tables
python -c "from app.db.session import SessionLocal; from app.ingestion.registry import seed_sources; seed_sources(SessionLocal())"
uvicorn app.main:app --reload
```
`ASTERA_MIGRATION_URL` overrides `DATABASE_URL` for Alembic only (used by the tests).

## Migration history
There is one revision, `0001_initial_schema`, **explicit** (`op.create_table`, generated by `alembic revision --autogenerate` against an empty PostgreSQL 16 and then edited to add `CREATE EXTENSION IF NOT EXISTS vector`). No migration calls `create_all()`.
**Reset note:** the two earlier revisions (0001 `create_all`-based, 0002 NASA tables) were replaced, and models changed (e.g. `catalogue_records`, `missions`, `artifacts`). They were never deployed anywhere known, so there was no data to preserve. **If you created a database with the earlier version, drop it and re-run `alembic upgrade head`; there is no upgrade path.** Re-run the catalogue ingestion afterwards.
`downgrade base` drops every table (destructive).
Future changes: edit models, run `alembic revision --autogenerate -m "..."`, review the diff by hand, commit. `tests/test_postgres.py::test_no_schema_drift_between_models_and_migrations` fails if models and migrations diverge.

## Validate on your machine
```bash
pytest -m pg -p no:logging        # needs `pip install pgserver` (embedded PostgreSQL 16 with pgvector); no Docker needed
```
These tests ran and passed in the build environment against PostgreSQL 16.2 with pgvector 0.6.2 (see PHASE_2_TEST_REPORT.md). They have **not** been run against your Docker image or a managed database; do that before deploying.
`knowledge_chunks.embedding` is `vector(384)` on PostgreSQL (JSON on SQLite). For similarity search use `app.domain.vectors.cosine_distance`; the ORM attribute alone has no distance operators. No ANN index exists yet; add an HNSW/IVFFlat index when the RAG phase has real data.
